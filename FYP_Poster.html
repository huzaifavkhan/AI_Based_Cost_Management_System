Problem: Manual Cost Tracking in Enterprise Procurement Workflows
Problem Overview / Background
Core Problem: Organisations lose 5–10% of annual spend to invoice fraud, duplicate payments, and manual entry errors because procurement cost data is locked inside unstructured paper and PDF documents.

Existing Approaches & Gaps
  1. ERP Manual Entry (SAP/Oracle): Error-prone, slow, requires trained operators
  2. Rule-Based OCR (Tesseract): Fails on scanned/degraded documents; no semantic understanding
  3. Commercial AP Automation: High licensing cost; centralises sensitive invoice data on vendor servers — a data-privacy risk

Key Observations
  • Layout variance: Invoices from 40+ vendors follow no common template
  • Mixed modalities: Data arrives as PDFs, scanned images, and typed emails
  • Semantic context required: "Total" must be disambiguated from "Sub-total" and "Tax"
Requirements for a Good Solution:
1. Extract fields accurately across varied invoice layouts
2. Automate PO–GR–Invoice 3-way matching
3. Train collaboratively without exposing raw invoice data (privacy)
4. Fine-tune efficiently with minimal compute & labelled data
Gap in Existing Solutions
  • No open-source tool combines OCR + NLP field extraction + 3-way match in one pipeline
  • All existing solutions require raw invoice data to be centralised — violating financial privacy regulations
  • Full fine-tuning of document models needs thousands of labelled invoices — unavailable for most SMEs
  • None provide integrated budget forecasting or anomaly detection
Our Goal: A privacy-preserving, compute-efficient AI pipeline using Federated Learning + LoRA that digitises invoices collaboratively without sharing raw data.
Solution: AI-Based Cost Management System
System Goals
  1. Achieve >90% field-extraction accuracy on real scanned invoices
  2. Fine-tune LayoutLM with LoRA — reducing trainable parameters by ~95%
  3. Train across multiple client organisations using Federated Learning (FedAvg) without sharing raw invoices
  4. Detect budget overruns and duplicate invoices in real time
Three core mechanisms:
  • LoRA Fine-Tuning: Adapts LayoutLM with low-rank weight updates only
  • Federated Learning: FedAvg aggregates LoRA adapters from N clients
  • Analytics Engine: 3-way matcher + anomaly detector + Streamlit dashboard

Key Components & Implementation
Anomaly Detection — 3 Layers
L1 Rules: duplicate invoice no., amount out of range, suspicious round number >$10k, invoice predates PO, weekend/stale (>90 days)
L2 Isolation Forest: unsupervised ML on amount, unit price & date lag — no fraud labels needed
L3 InvoiceAnomalyNet: MLP trained via FL — 7 engineered features, sigmoid >0.5 → FLAGGED

Results & Evaluation
Extraction & Matching:
  • FL+LoRA final accuracy: 87.9% (avg. F1 across 6 fields)
  • Centralised fine-tune: 92.9% — privacy gap only 5.4%
  • Best field — INVOICE_NO: 0.966 (FL) vs 0.999 (central)
FL & LoRA Efficiency:
  • Trainable params: 294K of 110M (LoRA r=8)
  • Communication: 1,152 KB/round vs 1.2 GB full FT (1,066× reduction)
  • Converges in 15 FL rounds across 3 clients (F1: 0.45→0.87)
  • Raw invoice data never leaves client — GDPR-safe

Conclusion & Future Work
Key Takeaways:

AI-Cost Management System combines a 4-tier extraction cascade, FL+LoRA fine-tuning (294K params, 1,066× less communication), and a 3-layer anomaly detector (Rules + Isolation Forest + InvoiceAnomalyNet) to achieve 87.9% field F1, only 5.4% below centralised while keeping all raw invoice data on-device.
Future Work:
  • Tighten DP: current ε≈8.74/round → target ε<5 via subsampling & σ tuning
  • Scale FL: 3 simulated clients → hundreds of real orgs with async aggregation
  • Multilingual: French+English → Arabic, Urdu, Asian scripts
  • Real-time streaming: process invoices from email/ERP webhooks with continuous FL
